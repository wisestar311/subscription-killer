# Catchup

Claude Code의 `/catchup`과 최대한 같은 순서와 판단 기준으로 동작한다.

## 0. 컨텍스트 초기화

가장 먼저 다음 명령을 실행한다.

```text
/clear
```

Skill 내부에서 `/clear`를 직접 실행할 수 없는 환경이면, 이후 판단에서 이전 대화 컨텍스트를 근거로 삼지 않고 현재 저장소 상태만으로 재구성한다.

## 현재 브랜치 변경 사항

Claude 원본과 동일하게 먼저 `main` 기준 변경 파일을 확인한다.

```bash
git diff --name-only main
```

`main` 브랜치가 존재하지 않으면 현재 저장소의 기본 브랜치 또는 적절한 비교 기준을 확인해서 사용한다.

정확도를 높이기 위해 다음 정보도 보조적으로 확인한다.

```bash
git status --short
git branch --show-current
git diff --stat
git diff
git log -5 --oneline --decorate
```

스테이징된 변경이 있으면 이것도 확인한다.

```bash
git diff --cached --name-only
git diff --cached --stat
git diff --cached
```

## 정리 지시

위에 나열된 각 파일을 읽고, 어떤 작업의 일부인지 파악한 다음 아래 형식으로 정리한다.

- 진행 중인 작업: (한 줄 요약)
- 완료된 변경: (파일별 간단 설명)
- 남은 작업: (TODO)
- 다음 단계: (지금 바로 할 일)

이 네 항목의 이름과 순서는 바꾸지 않는다.

## 판단 기준

Claude `/catchup`과 최대한 유사한 결과를 내기 위해 다음 원칙을 따른다.

1. 변경된 파일과 실제 diff를 가장 중요한 근거로 사용한다.
2. 최근 커밋은 작업 맥락을 보조하는 용도로만 사용한다.
3. 새 기능을 임의로 제안하거나 시작하지 않는다.
4. 이미 완료된 변경을 남은 작업으로 다시 분류하지 않는다.
5. 명확한 TODO, 미완성 코드, 실패한 검증이 있으면 남은 작업에 포함한다.
6. 추측이 필요한 부분은 사실처럼 단정하지 않는다.
7. 현재 작업과 관계없는 리팩터링은 제안하지 않는다.

## 필요한 경우에만 추가 확인

변경 내용을 이해하기 위해 필요한 경우에만 관련 파일, 호출부, 타입 정의, 테스트 파일을 추가로 읽는다.

프로젝트가 이미 lint/test/build 명령을 정의하고 있고 현재 작업의 완료 여부 판단에 필요한 경우에만 해당 검증을 실행한다. 존재하지 않는 명령을 임의로 만들지 않는다.

위험한 작업은 자동 실행하지 않는다.

- 배포
- 데이터 삭제
- 데이터베이스 마이그레이션
- `git reset --hard`
- 강제 push
- 대규모 파일 삭제
- 비용이 발생할 수 있는 외부 서비스 변경
- 보안 또는 권한 변경

## 작업 이어서 진행

정리 후 `다음 단계`가 명확하고 안전한 코드 작업이면 별도의 확인을 요구하지 말고 바로 이어서 진행한다.

다만 사용자의 의도가 여러 방향으로 갈리는 중대한 설계 변경이나 위의 위험 작업이 필요한 경우에는 진행하지 않고 현재 상태와 선택지만 짧게 제시한다.
